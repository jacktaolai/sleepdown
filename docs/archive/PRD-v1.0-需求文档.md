# Sleepdown 课程表应用需求文档

**版本**: v1.0
**日期**: 2026-02-19
**状态**: 待评审

---

## 1. 项目背景

### 1.1 问题陈述
当前市面上主流的课程表应用「xx课程表」都不够简洁易用，严重影响用户体验。用户每次打开应用都需要等待广告加载和跳过，违背了课程表应用"快速查看课表"的核心使用场景。

### 1.2 解决方案
开发一款无广告、轻量级、跨平台的课程表应用 **Sleepdown**（取自 Wake Up 的反义词），专注于提供纯粹、高效的课程表管理体验。

### 1.3 目标用户
- 在校大学生、研究生
- 需要管理课程表的学生群体
- 对广告敏感、追求简洁体验的用户

---

## 2. 产品概览

### 2.1 产品定位
一款轻量级、无广告、跨平台的智能课程表管理应用。

### 2.2 核心价值
- **无广告干扰**：纯粹的课表查看体验
- **智能导入**：多种方式一键导入课表
- **跨平台同步**：iOS / Android / 鸿蒙多端支持
- **高效触达**：桌面小组件，无需打开应用即可查看

### 2.3 技术选型
- **开发框架**: Flutter（实现 iOS、Android、鸿蒙跨平台）
- **UI 规范**: Material Design
- **存储**: 本地数据库

## 3. 功能需求

### 3.1 核心功能模块

#### 3.1.1 课程表展示

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 周视图 | 以周为单位展示课程表，横轴为星期，纵轴为节次 | P0 |
| 日视图 | 展示当日课程安排，按时间线排列 | P0 |
| 课程卡片 | 显示课程名称、地点、教师等信息 | P0 |
| 周次切换 | 支持切换不同周次查看课程 | P0 |
| 自动定位当前周 | 根据日期自动定位并显示当前周课程 | P0 |

#### 3.1.2 课程详情

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 点击查看详情 | 点击课程卡片弹出详细信息 | P0 |
| 详情内容 | 课程名称、教师、上课地点、上课时间、周次范围、学分等 | P0 |

#### 3.1.3 课程导入

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 教务网站导入 | 支持解析各高校教务系统网页，自动识别课程信息 | P0 |
| 自定义网页解析 | 用户可配置解析规则，适配未支持的教务系统 | P1 |
| 标准格式导入 | 支持导入iCalendar(.ics)、JSON等标准格式 | P1 |
| 手动添加 | 支持手动创建课程 | P0 |

> 待讨论点：
> - 标准格式导入不打算支持ics，考虑使用csv作为标准格式导入
> - 是否考虑复制粘贴导入（便于传播共享，但是要考虑文件长度是否超过主流平台限制，如微信）

#### 3.1.4 课程编辑

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 编辑课程信息 | 修改课程名称、地点、教师、时间等 | P0 |
| 删除课程 | 删除单节或整个课程 | P0 |
| 增加课程 | 支持手动添加新课程 | P0 |
| 课程重复设置 | 设置单周/双周/每周上课 | P1 |

#### 3.1.5 小组件（Widget）

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 桌面小组件 | 在桌面显示当日/当前课程 | P0 |
| 小组件尺寸 | 支持小、中、大多种尺寸 | P1 |
| 小组件刷新 | 定时自动更新显示内容 | P0 |
| 点击跳转 | 点击小组件跳转至应用 | P1 |

#### 3.1.6 时间管理

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 自定义节次时间 | 用户可设置每节课的开始和结束时间 | P0 |
| 自定义节次数量 | 支持设置每天的课程节数 | P0 |
| 作息时间模板 | 提供常用高校作息时间模板 | P2 |

---

### 3.2 用户体验需求

| 需求项 | 描述 | 优先级 |
|--------|------|--------|
| 快速启动 | 应用启动时间 < 1秒 | P0 |
| 无开屏广告 | 启动直达主页，无任何广告 | P0 |
| 定时更新 | 每日定时更新小组件和通知提醒 | P1 |
| 离线可用 | 核心功能无需网络即可使用 | P0 |
| 深色模式 | 支持跟随系统或手动切换深色模式 | P1 |

---

### 3.3 平台适配需求

| 平台 | 特殊需求 |
|------|----------|
| iOS | 支持 iOS 14+；适配 iOS Widget；适配灵动岛（P2） |
| Android | 支持 Android 6.0+；支持桌面小组件 |
| 鸿蒙 | 支持鸿蒙 4.0+；支持鸿蒙卡片服务 |

## 4. 非功能需求

### 4.1 性能要求
- 应用启动时间：< 1秒
- 页面切换流畅度：≥ 60fps
- 内存占用：< 100MB（前台运行时）

### 4.2 安全要求
- 用户数据本地加密存储
- 网络传输使用 HTTPS
- 不收集用户隐私数据

### 4.3 可维护性
- 模块化架构设计
- 完善的日志系统（用户可选开启）
- 热更新配置支持（教务网站解析规则）

## 7. 风险评估

| 风险项 | 影响 | 应对措施 |
|--------|------|----------|
| 教务网站解析维护成本高 | 大量高校教务系统需要适配 | 建立社区贡献机制；支持用户自定义解析规则 |
| 鸿蒙适配技术风险 | Flutter鸿蒙支持尚在发展 | 持续关注Flutter鸿蒙生态；必要时采用混合开发 |
| 小组件自动更新 | 自动更新权限设置是否过于复杂 | 调研方案 |

## 9. 附录

### 9.1 名词解释
- **节次**：每天课程的时间段划分，如第1-2节、第3-4节等
- **周次**：学期中的第几周，用于标识课程生效的时间范围
- **小组件**：桌面Widget，可在不打开应用的情况下显示课程信息
